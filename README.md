
1A2B 互動猜數字遊戲機
使用 NUCLEO-G474RE 搭配 Python 圖形介面，透過 UART 輸入猜測，並以四顆實體 LED 顯示每個位置的判斷結果。

開發板：NUCLEO-G474RE
系統時脈：170 MHz
通訊設定：LPUART1，115200 baud，8N1
操作方式：電腦輸入猜測，麵包板按鈕放棄／重開
1. 情境故事
傳統 1A2B 猜數字通常只有文字結果，不容易直接看出各位置的狀態。本專題讓玩家在電腦上輸入數字，由 STM32 判斷，再用四顆 LED 呈現全亮、呼吸或熄滅，增加實體互動感。

2. 替身對照
遊戲功能	實作方式
玩家輸入	Python Tkinter GUI，經 UART 傳送猜測
出題與裁判	STM32 產生答案並計算 A／B
四個位置的提示	四顆 LED，依序對應猜測第 1～4 位
數字、位置都正確（A）	對應 LED 全亮
數字正確、位置錯誤（B）	對應 LED 呼吸明暗
答案中沒有此數字	對應 LED 熄滅
放棄／重新開始	按麵包板按鈕，公布舊答案並開新局
3. 功能與驗收條件
功能	驗收方式	預期結果
隨機答案	開局輸入第一筆猜測	產生四個不重複數字，允許 0 開頭
輸入檢查	輸入重複、非數字或位數錯誤	GUI 阻擋送出；韌體亦檢查收到的資料
猜測比對	送出合法猜測	回傳回合、猜測數字及 A／B
燈光提示	比對猜測與答案	A 全亮、B 呼吸、錯誤熄滅
猜中答案	輸入正確答案	顯示 4A0B，四顆 LED 全亮
按鈕重開	按下麵包板按鈕	公布舊答案，換新答案，清除燈光與回合數
GUI 同步	接收新局訊息	清空本局紀錄，顯示上一局答案
判斷範例： 假設答案為 1234、猜測為 1478，結果為 1A1B。LED 1 全亮、LED 2 呼吸、LED 3 和 LED 4 熄滅。正式遊戲使用隨機答案。

實測紀錄： 已完成編譯、燒錄及本機遊戲／GUI 操作；尚未附逐項驗收截圖，也未留下長時間運轉與快速連續操作的量測紀錄。

4. 技術勾選

GPIO 輸出／複用功能：四路 TIM3 PWM 驅動 LED。

GPIO 輸入：PA0 按鈕，內部上拉。

RCC 與 PLL：系統時脈 170 MHz。

Timer：TIM3 提供 PWM 計數及亂數種子取樣值。

PWM：控制四顆 LED 全亮、熄滅及呼吸。

UART 傳送／接收：LPUART1，採輪詢接收。

EXTI 外部中斷：PA0 下降沿觸發。

NVIC：啟用 EXTI0，優先權為 2。

軟體防重複觸發：200 ms 內忽略重複按鈕中斷。
UART 中斷接收與環形緩衝：尚未實作。
Timer 週期中斷：呼吸亮度由主迴圈更新。
Timer 輸入捕捉：目前未使用。
PWM 使用 Prescaler = 169、Period = 999，頻率為 1 kHz。比較值 0 為熄滅，1000 為全亮；呼吸週期為 1 秒漸亮、1 秒漸暗。

5. 腳位與接線
腳位	功能	用途
PA6	TIM3_CH1	LED 1，對應猜測第 1 位
PA7	TIM3_CH2	LED 2，對應猜測第 2 位
PB0	TIM3_CH3	LED 3，對應猜測第 3 位
PB1	TIM3_CH4	LED 4，對應猜測第 4 位
PA0	GPIO_EXTI0	麵包板重來按鈕，上拉、下降沿觸發
PA2	LPUART1_TX	STM32 傳送至 ST-LINK VCP
PA3	LPUART1_RX	STM32 接收 ST-LINK VCP 資料
PA13／PA14	SWDIO／SWCLK	燒錄與除錯
GND	共地	LED 負極與按鈕另一端
每顆 LED 各自串接一顆 330 Ω～1 kΩ 電阻，負極接 GND。
按鈕接在 PA0 與 GND 之間，選用按下後才導通的兩端。
板載 B1（PC13）及 LD2（PA5）未作為主要遊戲按鈕與提示燈。
6. 建置與執行
開發環境
韌體：C、STM32 HAL、STM32CubeMX、STM32CubeIDE 2.2.0。
電腦端：Python 3、Tkinter、pySerial，可使用 PyCharm 執行。
材料：開發板、LED × 4、電阻 × 4、按鈕 × 1、麵包板、杜邦線、USB 資料線。
STM32 韌體
在 CubeIDE 匯入專案，接上板載 ST-LINK USB。
確認 .ioc 設定為 170 MHz、LPUART1 115200、TIM3 四路 PWM、PA0 EXTI0。
執行 Build Project，確認沒有錯誤。
使用 Run／Debug 燒錄；若停在 main()，按 F8 繼續。
Python 圖形介面
將 UART_GUI.py 放入工作資料夾。若 repository 尚未包含此檔，需一併上傳。

python -m pip install pyserial
python UART_GUI.py
選擇實際 COM 埠並連線；開發時使用 COM3。
輸入四個不重複數字，按 Enter 或 送出猜測。
查看 GUI 結果及四顆 LED。
按麵包板按鈕公布答案並重新開局。
串口使用 115200、8N1、無流量控制。每筆猜測以換行結尾，例如 1478\n。

以下為通訊格式示例，假設該局答案為 1234；按下重來按鈕後才會公布答案：

STM32 UART Ready. Enter 4 different digits.
Round 1: 1478 -> 1A1B
Answer: 1234
New game!

中斷回呼： 判斷按鈕觸發間隔，設定 restart_requested 旗標。
主迴圈： 處理重開、輪詢接收、收到換行後比對，持續更新 PWM。
GUI： 背景接收串口資料，透過佇列交由介面執行緒顯示；A／B 由 STM32 計算。
隨機答案： 首次輸入非換行字元或首次按鈕重開時，以 HAL_GetTick() 與 TIM3 計數值作為種子。使用 rand() 產生四個不重複數字，並排除與上一局相同的答案。

9. AI 使用與查核
使用 ChatGPT 協助 CubeMX 設定、C 程式撰寫與除錯、Python GUI 及 README 整理。

查核方式包括 CubeIDE 編譯與燒錄、本機串口及 GUI 操作、燈光與按鈕測試。開發中曾修正括號錯置、中斷函式重複及鮑率不一致等問題。

另以電腦端模擬檢查遊戲判斷及 10,000 次換局，確認四位數不重複且相鄰局答案不同。模擬測試不取代硬體驗收。

10. 已知限制與改善方向
目前限制	改善方向
UART 採輪詢，快速連續輸入可能漏字	改用中斷／DMA 與環形緩衝
呼吸效果由主迴圈更新	加入固定週期排程或 Timer 中斷
按鈕使用 200 ms 簡易防重複觸發	量測按鈕彈跳並改善去彈跳
猜中後不自動換題，也未鎖定輸入	加入遊戲結束狀態與換題機制
GUI 關閉後不保存紀錄，重新連線不會重設板子	加入紀錄匯出與遊戲狀態同步
本專題使用 USB 串口、單色 LED 及偽隨機答案，尚未加入網路、RGB 或硬體真亂數。答案只排除相鄰局重複，不保證所有歷史局皆不同。
