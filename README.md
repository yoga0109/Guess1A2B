1A2B 互動猜數字遊戲機（NUCLEO-G474RE 期中專題）
透過電腦上的 Python 圖形介面輸入猜測，由 STM32 判斷 A／B 結果，並用四顆實體 LED 顯示各位置的狀態。按下麵包板按鈕，即可公布答案並重新開局。
1. 情境故事：誰、在哪、遇到什麼麻煩
玩家在電腦前進行 1A2B 猜數字遊戲時，通常只能看到文字結果，較難直接理解每一個輸入位置的判斷狀態。
本專題將猜數字遊戲與微控制器結合：玩家使用電腦輸入數字，STM32 負責答案產生與比對，再以 LED 的全亮、呼吸與熄滅呈現回饋，增加實體互動感，也讓 UART、GPIO、PWM 與中斷的應用更容易觀察。

4. 用到的技術：對照課程技術勾選表
以下依目前程式實作整理，可對照課程第 3～7 週勾選表與投影片。
勾選	技術	本專題實作
[x]	GPIO 輸出／複用功能	四個腳位設為 TIM3 PWM 複用輸出，驅動 LED
[x]	GPIO 輸入	PA0 接麵包板按鈕，使用內部上拉
[x]	RCC 與 PLL	以 HSI 16 MHz 經 PLL 設定系統時脈為 170 MHz
[x]	Timer	TIM3 提供 PWM 計數與種子取樣所用的計數值
[x]	PWM	四路獨立設定比較值，控制全亮、熄滅與呼吸
[x]	UART 傳送／接收	LPUART1 與電腦交換文字訊息；接收採輪詢方式
[x]	EXTI 外部中斷	PA0 下降沿中斷觸發重開要求
[x]	NVIC	啟用 EXTI0 中斷，優先權設定為 2
[x]	軟體按鈕防重複觸發	接受按下後，200 ms 內忽略重複中斷
[ ]	UART 中斷接收與環形緩衝	目前未實作，使用 `HAL_UART_Receive()` 與固定長度猜測陣列
[ ]	Timer 週期中斷	呼吸亮度由主迴圈依 `HAL_GetTick()` 更新，未使用 TIM3 週期中斷
[ ]	Timer 輸入捕捉	目前未使用
PWM 設定：TIM3 時脈為 170 MHz，Prescaler = 169，Counter Period = 999，因此 PWM 頻率為 `170,000,000 / (170 × 1000) = 1000 Hz`。比較值 0 為熄滅、1000 為全亮；呼吸效果每 1 秒漸亮、1 秒漸暗。
5. 腳位表：用到的每支腳與用途
STM32 腳位	功能	接線／用途
PA6	TIM3_CH1	第 1 顆 LED，對應猜測第 1 位
PA7	TIM3_CH2	第 2 顆 LED，對應猜測第 2 位
PB0	TIM3_CH3	第 3 顆 LED，對應猜測第 3 位
PB1	TIM3_CH4	第 4 顆 LED，對應猜測第 4 位
PA0	GPIO_EXTI0	麵包板按鈕；內部上拉、下降沿觸發
PA2	LPUART1_TX	STM32 傳送資料至板載 ST-LINK VCP
PA3	LPUART1_RX	STM32 接收板載 ST-LINK VCP 的資料
PA13／PA14	SWDIO／SWCLK	ST-LINK 燒錄及除錯
GND	共地	LED 負極與按鈕另一端
每顆 LED 各自串接一顆 330 Ω～1 kΩ 電阻：輸出腳位 → 電阻 → LED 正極，LED 負極 → GND。
按鈕接在 PA0 與 GND 之間。四腳按鈕須選擇「按下後才導通」的兩端。板載 B1（PC13）與 LD2（PA5）未作為本遊戲的主要按鈕及四路提示燈。
6. 建置與執行：開發環境、燒錄步驟、終端機設定、命令
開發環境
開發板：NUCLEO-G474RE。
韌體：C、STM32 HAL、STM32CubeMX、STM32CubeIDE 2.2.0。
電腦端：Python 3、Tkinter、pySerial；可使用 PyCharm 執行。
硬體材料：LED × 4、限流電阻 × 4、按鈕 × 1、麵包板、杜邦線與可傳輸資料的 USB 線。
韌體建置與燒錄
在 STM32CubeIDE 匯入此專案。
確認 `Guess1A2B.ioc` 的 LPUART1 為 115200、8N1，TIM3 四路 PWM 與 PA0 EXTI0 設定正確。
使用板載 ST-LINK 的 USB 接口連接電腦。
執行 Build Project，確認沒有編譯錯誤，再使用 Run／Debug 燒錄。
使用 Debug 時，如果程式停在 `main()`，按 F8 繼續執行。
`EXTI0_IRQHandler()` 只能定義一份，且必須呼叫 `HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_0)`。
電腦 GUI
將 `UART_GUI.py` 放入電腦端工作資料夾；若尚未加入此 repository，請一併上傳，讓其他人能取得同一版程式。使用同一個 Python 環境執行：
```bash
python -m pip install pyserial
python UART_GUI.py
```
啟動後選擇實際 COM 埠並連線。開發時使用 COM3，但不同電腦的埠號可能不同。輸入四個不重複數字，按 Enter 或「送出猜測」；重開新局請按麵包板按鈕。
使用標準 Python Windows 安裝時通常已包含 Tkinter；若缺少，可先執行 `python -m tkinter` 檢查安裝環境。
串口設定與訊息格式
項目	設定
鮑率	115200
資料位元	8
同位檢查	None
停止位元	1
流量控制	None
猜測命令	四個不重複數字，以 LF 結尾，例如 `1478\n`；韌體亦接受 CR／CRLF
STM32 回傳範例：

7. 程式結構：哪個檔做什麼、ISR 與主迴圈分工
檔案	職責
Src/main.c	周邊初始化、產生答案、接收猜測、計算 A／B、更新 LED、處理重開
Src/stm32g4xx_it.c	中斷入口；EXTI0 轉交 HAL 處理
Src/stm32g4xx_hal_msp.c	周邊時脈、UART 與 PWM 複用腳位初始化
Inc/main.h	主程式共用宣告與 CubeMX 腳位定義
Guess1A2B.ioc	CubeMX 專案設定
`UART_GUI.py`	電腦端串口連線、輸入檢查、結果顯示、猜測歷史與通訊紀錄
按鈕處理流程：EXTI0 中斷入口 → HAL GPIO 中斷處理 → `HAL_GPIO_EXTI_Callback()` → 設定 `restart_requested` → 主迴圈公布舊答案並重開。
中斷回呼只判斷時間間隔並設定旗標，不在中斷內傳送 UART 或執行遊戲比對。
主迴圈每次輪詢接收一個字元，收到換行後才檢查並比對完整猜測，同時依各位置的 `led_state` 更新四路 PWM。
`GenerateAnswer()` 在首次收到非換行字元，或首次按下重來按鈕時，取 `HAL_GetTick()` 與 TIM3 計數值作為種子，使用 `srand()`／`rand()` 產生偽隨機答案。之後每次重開延續亂數序列，並排除與上一局完全相同的答案。
GUI 的接收執行緒讀取串口，經佇列交給 Tkinter 主執行緒更新畫面；A／B 判斷仍由 STM32 完成。

10. 已知限制：哪些用替身、換真實要改哪裡
本專題以 LED 的亮度與呼吸效果作為狀態提示，不是 RGB 顏色切換；GUI 是電腦端操作介面。
使用 USB 虛擬串口互動，尚未實作 Wi-Fi、藍牙或網際網路連線。
UART 目前為輪詢接收與固定長度陣列；快速連續傳送時，尤其韌體正在回傳文字期間，可能遺失資料。後續可改成中斷／DMA 接收與環形緩衝。
呼吸效果由主迴圈更新，主迴圈受阻時亮度更新也會延後；後續可加入固定週期排程或 Timer 中斷。
答案採偽隨機方式，非硬體真亂數；只保證不與上一局相同，不保證歷史所有局都不重複。
200 ms 防重複觸發屬簡易處理，未量測實體按鈕的完整彈跳波形。
猜中後不會自動換題，也未鎖定後續輸入；按麵包板按鈕才會重開。
GUI 重新連線會清空畫面紀錄，但不會自動重設 STM32 遊戲；需要同步開新局時請按麵包板按鈕。
GUI 紀錄保存在記憶體中，關閉後不保存；電腦 COM 埠與元件接線須依實際環境確認。
`.ioc` 必須與最後使用的韌體設定一致；重新產生程式碼後，須重新核對鮑率、PWM、PA0 EXTI、NVIC 及中斷入口。
